# Litmus tests for baremetal RTL validation

This directory automates building memory-consistency litmus tests from the
[litmus-tests-riscv](https://github.com/litmus-tests/litmus-tests-riscv)
submodule (under `sw/litmus-tests-riscv/`) as baremetal binaries for the
system-level RTL DUT.

## Layout

```
sw/
├── litmus-tests-riscv/         # upstream submodule (.litmus sources)
└── litmus/
    ├── README.md
    ├── harness.h               # baremetal harness: barrier + tohost reporting
    ├── port.py                 # .litmus → baremetal C translator
    └── ported/                 # generated C tests (gitignored)
```

## Quick start

```bash
cd sw

# Translate a single test
./litmus/port.py litmus-tests-riscv/tests/non-mixed-size/BASIC_2_THREAD/MP.litmus \
                 litmus/ported/MP.c

# Or batch-translate everything under a directory
./litmus/port.py --batch litmus-tests-riscv/tests/non-mixed-size

# Build all ported tests (HARTS forwarded as PITON_NUMTILES to crt.S)
make litmus HARTS=2 -j$(nproc) -k

# Load a single test onto the RTL DUT
make litmus_load TEST=MP

# Per-test artefacts
make build/litmus_MP.bin    HARTS=2   # baremetal binary
make build/litmus_MP.dis    HARTS=2   # disassembly
make build/litmus_MP.trace  HARTS=2   # whisper trace
```

`HARTS=N` is forwarded to both `crt.S` (`-DPITON_NUMTILES=N`) and whisper
(`--harts N`). Default is 2. The baremetal `_init` from `syscalls.c` calls
the test's `main()`, which is generated by `port.py`.

## How `port.py` works

For each `.litmus` source it generates a self-contained C file that:

1. Declares the shared locations as a `litmus_ctx` struct.
2. Emits one `pN(out)` function per thread containing:
   - `register int64_t reg_<r> asm("<r>") = ...;` bindings, pinning
     C variables to the specific physical registers the test names.
   - An `asm volatile { ... }` block with the test's instruction sequence
     verbatim (with pseudo-mnemonic expansion — see below).
   - Saves of any registers referenced by the final-state predicate.
3. Translates the `exists`/`forall` predicate into a C boolean expression
   (`/\` → `&&`, `\/` → `||`, `i:rN` → `out_pi.rN`, location names → `ctx.X`).
4. Drives `LITMUS_NRUNS` iterations from `main()`, with hart 0 resetting
   state, all harts hitting a software sense-reversing barrier on entry
   and exit, and hart 0 evaluating the predicate per iteration.
5. Reports pass (`tohost = 2`) or fail (`tohost = 1`) via the standard
   `cosim.h` convention used by the rest of `sw/`.

### Pseudo-mnemonic expansion

Litmus shorthand `lw.aq` / `sw.rl` (which are not real RISC-V opcodes)
are expanded to the fence-based release/acquire pattern:

```
sw.rl x5,0(x6)   →   fence rw,w ; sw x5,0(x6)
lw.aq x5,0(x6)   →   lw x5,0(x6) ; fence r,rw
```

Real `.aq`/`.rl` AMOs (e.g. `amoswap.w.aq.rl`) are passed through
unchanged — they are valid RISC-V instructions.

## Coverage

The script handles standard non-mixed-size tests with RISC-V baseline
opcodes (RVI + A + Zifencei + load-acquire/store-release shorthand).

Tests that need manual help:

- **Mixed-size tests** (under `tests/mixed-size/`) — overlapping byte/half/
  word accesses; need additional context-struct marshalling.
- **DVM / hypervisor / supervisor tests** — privileged instruction sequences
  the bare-metal `crt.S` does not set up.
- **Tests with non-standard opcodes** — e.g. `amocas.*` (zacas extension)
  may need an updated toolchain. Use `make litmus -k` to continue past
  individual failures.

Use `-k` (`--keep-going`) when batch-building so individual failures don't
abort the whole run.

## Notes

- `ported/` is gitignored — regenerate from the submodule rather than
  committing thousands of generated C files. Commit specific ports only
  when you've hand-tuned them.
- The harness uses the same `crt.S` / `link.ld` as the rest of `sw/`, so
  binaries boot identically on the RTL DUT and behave the same way under
  `whisper` for golden-trace comparison.
